# Слабые стороны agent-memory на фоне конкурентов

Честный разбор позиции agent-memory относительно пейзажа memory-систем: **Cognee,
Supermemory, Honcho, Hindsight, EverMemOS (EverMind), Letta, ECC**, а также
ранее изученных **AEndrix03/Graft**, **trailhq/graft** и **tickernelz/opencode-mem**.

Назначение файла — дорожная карта и защита позиции при сравнении: что чинить
первым, что честно называть границей продукта, а что — осознанным trade-off.

**Как читать Severity:**
- **S1** — по этому будут сравнивать в таблицах и об этом спросят первым;
- **S2** — заметно при реальной эксплуатации или при оценке;
- **S3** — позиционирование, инфраструктура, границы рынка.

---

## 1. Разрыв в качестве извлечения (recall/distillation quality) — S1

**Факты.** Наши опубликованные цифры: **52.9% на LongMemEval-S** (bounded haystack,
хост — Haiku 4.5, study стратегии записи записи). У конкурентов:

| Система | Бенчмарк | Цифра | Условия |
|---|---|---|---|
| agent-memory | LongMemEval-S | 52.9% | bounded haystack (12 эпизодов), Haiku-хост |
| Hindsight | LongMemEval | **83.6%** | **открытая 20B-модель** |
| Hindsight | LongMemEval | **91.4%** | Gemini-3 Pro |
| Hindsight | LoCoMo | 89.61% | — |
| Supermemory | LongMemEval / LoCoMo / ConvoMem | заявляет #1 | полный бенчмарк |
| Honcho | LoCoMo | 86.9% | SOTA-заявка |
| EverMemOS | LoCoMo / LongMemEval | +9.2% / +6.7% к лучшему бейзлайну | статья ACL |
| Letta (файловые тулзы) | LoCoMo | 74% | GPT-4o mini |
| Cognee, ECC, opencode-mem | — | нет опубликованных | — |

**Почему это S1, а не «нечестное сравнение».** Оговорка в README честная
(haystack ограничен, это study стратегии записи, хост слабый), но она работает
в обе стороны: ограниченный haystack *упрощает* задачу, а разрыв — 30+ процентных
пунктов. Главный контраргумент против оговорки: **Hindsight выжимает 83.6% из
открытой 20B-модели** — то есть слабый хост объясняет не всё, и разрыв в
качестве дистилляции и retrieval скорее реален.

**Диагноз (где именно может теряться):**
- дистилляция через чужой хост-CLI привязана к случайному модельному стеку
  пользователя — нет своего обученного/калиброванного экстрактора (см. п. 2);
- read path по умолчанию — только BM25 (см. п. 4);
- нет rerankera и второго прохода «достаточно ли найдено» (см. п. 4);
- gate уверенности по title и самореференс (рефлексия может помнить о себе) —
  ранее найденные слабости, остаются.

**Что чинить (в TODO уже отражено частично):** `recall --explain` (диагностика,
почему не нашли), гейт уверенности по abstract+body, вектор/обход links в recall,
reranker, честный прогон на полном бенчмарке ради сравнимой цифры.

## 2. Запись медленная, чужая и некалиброванная — S1

**Факты.** Дистилляция границы на Haiku занимает **80–100 секунд** (задокументировано
в TODO): три раунда переговоров с хостом, холодный процесс каждый раз, логин
заимствуется у хост-CLI. Каждая граница сессии платит эту цену.

**У кого решено лучше:**
- **Supermemory** — секунды (instant dreaming), плюс отдельный режим dynamic
  (батчами по связанным документам);
- **Honcho** — фоновая очередь рассуждений, и главное: **свои обученные
  маленькие модели** (Neuromancer XR, дообученный Qwen3-8B) — задача извлечения
  решена как отдельный модельный продукт;
- **opencode-mem** — один LLM-запрос на idle;
- **EverMemOS** — калиброванный выход: ровно 2–5 нарративных фактов на диалог;
- **Hindsight** — retain-пайплайн при ingеste, не на границе сессии.

**Суть.** Дистилляция заимствует чужой CLI: качество = качество случайной модели
пользователя, скорости нет, регулирования объёма нет (сколько фактов извлекать —
не нормировано). Это вторая вещь, по которой будут сравнивать.

**Что чинить:** свой дешёвый reasoner (или endpoint opt-in, уже есть в планах
профилей) + нормирование объёма извлечения; опционально — нормализация latency
через предсогрев/пул процессов.

## 3. Нет моделирования пользователя первого класса — S1/S2

**Факты.** Почти у всех полей есть «что мы знаем о пользователе»:

| Система | Механизм |
|---|---|
| Honcho | peer representations, выводы 4 типов уверенности, peer cards (главное оружие) |
| Supermemory | профили в temporal graph |
| Hindsight | observations + opinions с confidence, behavioral-профиль (CARA) |
| EverMemOS | user profile с conflict tracking |
| Letta | core memory `human` block |
| opencode-mem | profile learning |

У agent-memory — MEMORY.md и типизированные мемори, но **«что стор знает о тебе
как о пользователе» как отдельной сущности нет**: нет инвариантов о человеке,
предпочтений, рабочих привычек, отдельных от знаний проекта.

**Почему это важно:** (a) персонализация — базовое ожидание 2026 года;
(b) для будущего UI-экрана «что агент обо мне знает» (кейс витрины) — прямой
пробел; (c) для recall по «как я обычно делаю X» — нет объекта запроса.

**Что чинить:** TODO-пункт профилей (профили + `--profile`) уже записан — это
закрывает и пробел, и UI-витрину.

## 4. Извлечение лексическое по умолчанию, а построенный граф не используется в read path — S1

**Факты.** Норма индустрии 2026:
- **Hindsight** — 4 параллельных канала (вектор + BM25 + spreading activation по
  графу + временной фильтр) → RRF → **cross-encoder** → token budget;
- **Cognee** — 14 режимов, граф+вектор+BM25 по RRF;
- **EverMemOS** — dense+BM25 RRF + траверсинг MemScene + sufficiency-verifier.

У agent-memory: по умолчанию **BM25**; вектор — плагин, опционален и выключен;
**links во frontmatter живут в данных, но recall по ним не ходит** — ни spreading
activation, ни обхода соседей, ни агрегации веса по рёбрам. Rerankera нет.

**Суть.** Мы честно строим граф связей и не потребляем его в ранжировании —
данные лежат мёртвым грузом. Потолок recall — точность фразировки запроса.
Оговорка: L0-пути (отдаём файл, читает агент) — осознанный дизайн, и Letta-бенчмарк
«файловые тулзы = 74% LoCoMo» его поддерживает; но это не отменяет отсутствия
graph-aware ranking.

**Что чинить:** обход links в recall (траверсинг 1–2 хопа с затуханием), вектор
по умолчанию в дистрибуции, reranker как второй проход; `--explain` покажет
вклад каналов.

## 5. Слабое обнаружение противоречий и устаревания — S2

**Факты.** У конкурентов авто-механики: Supermemory — «updates win» + time-decay;
Cognee — detect_contradictions; EverMemOS — conflict tracking при кластеризации;
Hindsight — refine-not-overwrite с proof counts. У нас supersede **явный**
(агент сам зовёт `record --supersedes`), противоречия ловит только sleep-проход —
и то опционально и завися от качества хост-рассуждения. `invalid_at` ставится
только явными операциями. Протухшая активная мемори может жить, пока никто не
заметит.

**Оговорка (осознанный trade-off).** Авто-забывание без человека — это ровно то,
чем мы отличаемся в лучшую сторону (T1-пропозалы, честность > автоматизма).
Слабость не в «нет авто-перезаписи», а в **слабом детектировании**: кандидат
на supersede никто не находит, пока sleep не заметит. Ранее записанный TODO
(таксономия maintenance-кандидатов с детерминированными id, link proposals через
T1) — прямое лекарство.

## 6. Фрикция установки и сопровождения — S2

**Факты.** Наш первый контакт: `git clone && uv sync` (PyPI нет), PATH,
`setup` на каждый хост, доверие хукам Codex (sandbox writable roots), песочница
Muse с ограничениями записи, pproxy как внешняя зависимость, preflight с живыми
запросами. У конкурентов:

| Система | Первый контакт |
|---|---|
| Hindsight | `pip install hindsight-all`, drop-in обёртки OpenAI/Anthropic |
| opencode-mem | одна строка в `opencode.json` |
| Cognee | `pip install cognee` |
| Supermemory | SDK + ключ |
| ECC | часть их harness, ставится с системой |

**Суть.** Мультихостность — сила и одновременно 4+ адаптеров (hooks × MCP ×
диалекты × sandbox), которые надо поддерживать вечно. Для оценивающего это самая
толстая стена из всех участников.

**Что чинить:** релиз в PyPI (или `uv tool install agent-memory`), один-клик
установщик на хост, стабильный `doctor`.

## 7. Нет мультитенантности и командного сценария; security-долг перед ним — S2

**Факты.** Cognee — права на датасеты (read/write/delete/share); Supermemory —
неймспейсы + scoped keys; Honcho — workspaces; EverMemOS — group-чаты. У нас —
один локальный стор на одного пользователя; shared-сценарий не спроектирован.
И задокументированный долг: **sleep коммитит весь корень стора, включая сырые
транскрипты с возможными секретами/PII** (TODO, security) — не закрыто.

**Суть.** Это не баг текущего режима (local-first, один юзер — наш дизайн), но
(а) командное использование невозможно, (б) до закрытия security-долга любой
shared-режим опасен, (в) репозиторий стора содержит чувствительное сырьё.

## 8. Задержка доступности знаний в текущей сессии — S2

**Факты.** Capture на границе → дистилляция по расписанию/на старте. «Узнал в
сессии — применил в этой же сессии» работает только через ручной `/mem-distill`
или по расписанию. Конкуренты: Supermemory instant mode, Hindsight retain на
ingest, opencode-mem — capture на idle с немедленной инъекцией в промпт.

**Суть.** Пока дистилляция не отработала — recall не увидит знание. Для
long-running сессии это ок (sleep всё равно нужен), для коротких — разрыв.
Частично закрывается частым sleep по событию (расписание есть), но по умолчанию
latency-история слабее, чем у «instant»-конкурентов.

## 9. Нет UI и визуализации — S2 (главный мотив текущего проекта)

**Факты.** Supermemory — WebGL-граф + дашборд; Cognee — HTML-визуализация
графа; Hindsight — интерактивный benchmark-viewer; trailhq/graft — `graft viz`;
opencode-mem — полный web UI (timeline memory↔prompt, REST API); AEndrix03/Graft
— свой viewer. У нас — ни экрана: только CLI и файлы.

**Суть.** Для отладки «что память знает / почему не нашла / что пропозал sleep»
— единственный путь чтение файлов руками. Это ровно тот пробел, под который
заточен проект `agent-memory-ui` (Store Explorer, Proposals Console, Retrieval
Debugger, витрина — см. `ui-notes.md`).

## 10. Зрелость и дистрибуция — S2/S3

**Факты.** 0.1.0, установка из чекаута, ~0 сообщества. У конкурентов: Hindsight —
13.3k ★ MIT; Cognee — продакшн 70+ компаний, ~1M пайплайнов/мес; Supermemory —
продукт с коннекторами и pricing; Letta — большая экосистема; Honcho — managed-сервис.

**Суть.** Уникальные 4 свойства (авто-capture с гарантией доставки + человек
обязателен для деструктивного + ноль-ключевой локальный read path + trace до
сырого сообщения) — настоящие, но они не упакованы: ни одной сравнимой цифры на
полном бенчмарке, ни одного лендинга, ни установки в одну команду. Никто не
начнёт с `git clone && uv sync`, пока причина не станет очевидной и дешёвой
в попытке.

## 11. Узость покрытия (граница рынка, не баг) — S3

**Факты.** Наш сценарий — текст + coding-хосты в CLI. У конкурентов шире:
Supermemory — мультимодал (PDF/видео/картинки) + коннекторы (Notion, Drive,
GitHub); Honcho — любая сущность (роль-плей, тьюторы, NPC); Cognee — онтологии
и произвольные документы; opencode-mem — scope-переключатели (personal/project).

**Суть.** Это граница рынка, её надо называть вслух, а не прятать. Для
позиционирования «память для агентов-кодеров в CLI» — нормально; для претензии
«memory layer вообще» — нет.

## Приоритеты чинки

1. **Качество recall** (п. 1 + п. 4): `--explain` для диагностики, обход links,
   вектор/реранкер, и — отдельно — честный прогон на полном бенчмарке ради
   сравнимой цифры.
2. **Дистилляция** (п. 2): свой дешёвый reasoner / endpoint opt-in + нормирование
   объёма извлечения вместо 80–100 с на чужом CLI.
3. **Профиль пользователя** (п. 3): сущность первого класса + `--profile`
   (уже в TODO) — закрывает и фичу, и кейс витрины UI.

Остальное — позиционирование (п. 11), инфраструктура (п. 6, 7) или осознанные
trade-off (п. 5, 8), которые надо называть, а не чинить срочно.

## Граница «недостаток vs осознанный trade-off»

Чтобы при сравнении не защищаться лишний раз, явно:

| Поведение | Это |
|---|---|
| Нет авто-записи без человека (T1) | **Trade-off** — наше преимущество |
| L0-пути (агент читает файлы) | **Trade-off** — поддержан Letta-бенчмарком |
| BM25 по умолчанию без обхода links | **Недостаток** — граф не читается в recall |
| Суперсединг только явный | **Недостаток** в детектировании, trade-off в исполнении |
| Локальный однопользовательский стор | **Trade-off** сейчас, **недостаток** для команд |
| Текст + coding-хосты | **Граница рынка** |
